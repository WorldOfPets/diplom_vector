# Безопасность

## Что уже сделано

- Данные дневника (`cause`, `body_zones`, `note`) шифруются на уровне приложения.
- Ключ шифрования выводится из `APP_KEY` и идентификатора владельца записи, поэтому ciphertext одной записи нельзя расшифровать в контексте другого пользователя.
- Записи дневника выбираются и удаляются только через контроллер с проверкой `user_id`.
- Пароли не хранятся: вход в production идёт через Яндекс OAuth.
- Секреты не попадают в репозиторий: `.env` и локальная SQLite-база исключены через `.gitignore`.
- Камера обрабатывает кадры в браузере; видео и кадры не отправляются на сервер.

## Важное ограничение

Это шифрование at rest. Сервер с `APP_KEY` и доступом к базе технически может расшифровать данные приложения. Полная end-to-end схема потребовала бы отдельного пароля или ключа, который хранится только у пользователя; для входа через Яндекс OAuth такой ключ неоткуда безопасно взять на новом устройстве.

## Сообщить об уязвимости

Не создавайте публичный issue с секретами, персональными данными или рабочим эксплойтом. Сообщите администратору проекта или куратору, указав:

- версию/коммит;
- шаги воспроизведения;
- ожидаемое и фактическое поведение;
- возможное влияние.

Не прикладывайте реальные записи дневника и токены доступа.
